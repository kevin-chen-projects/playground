# Architecture Notes\n\n## Current implementation\n\nThis project uses a lightweight full-stack structure:\n\n- Frontend: plain HTML/CSS/JS upload UI\n- Backend: FastAPI\n- Transcription core: Spotify Basic Pitch\n- Guitar adaptation:\n  - simultaneous note grouping into chord events\n  - basic chord labeling\n  - fretboard placement heuristics by tuning\n- Output rendering: ReportLab PDF\n\n## Why this design\n\nA real MP3-to-guitar-score system has several separate problems:\n\n1. Audio decoding\n2. Polyphonic pitch estimation\n3. Timing segmentation\n4. Chord grouping\n5. Guitar-specific fingering inference\n6. Score rendering\n\nUsing `Basic Pitch` solves step 2 reasonably well for a prototype.\nThe custom Python layer addresses steps 3–6 at a basic heuristic level.\n\n## Tradeoffs\n\n### Strengths\n- Fully local and hackable\n- Good prototype for isolated guitar recordings\n- Produces a real downloadable PDF artifact\n- Easy to extend\n\n### Weaknesses\n- Not true engraved notation\n- Guitar tab is inferred, not recovered from original performance technique\n- Chord naming is simplistic\n- Rhythm notation is minimal\n- No explicit barline/measure reconstruction\n\n## Better future architecture\n\nFor a stronger system, use:\n\n- source separation first\n- Basic Pitch or a stronger guitar-specific AMT model\n- MIDI cleanup and quantization\n- MusicXML generation\n- LilyPond or MuseScore CLI rendering to PDF\n- optional human correction interface before export\n
